## 四篇论文

### [01-三值GEMM交叉点](01-三值GEMM交叉点.md)

路线 A。三值权重在带宽受限推理中的优势**及其交叉点**。

核心结论：最大规模下比 int4 快 **1.92x**、比 fp16 快 **7.65x**；
但 **N=512 时 int4 反超**，因为此时权重完全驻留 L2，瓶颈从带宽变成解包指令。

> 这是本文相对已有工作的主要修正：把「三值总是更快」当作无条件结论是错的。

### [02-联想记忆工具路由](02-联想记忆工具路由.md)

路线 B，主路线。**零训练参数**的对话工具路由。

核心结论：6750 条教学句，留出集工具名准确率 **100%**，写入 **23.1 µs/条**，
检索 **0.219 ms**；真实语料域外误执行率 **1.3%**（英文）/ **0.3%**（中文）。

> 明确承认边界：**不具备组合泛化**，对没见过的动词选择拒答。
> 在工具路由场景下这是特性，在开放域是缺陷。

### [03-语境许可](03-语境许可.md)

参数提取的方法论。**一个符号不构成证据，直到语境为它颁发许可。**

核心结论：三级证据强度 **形状 < 词汇 < 上下文关系**，
每一级都由一个真实失败案例逼出来。

> 最重要的单条经验：**当一个豁免同时回答了两个问题，它就会在其中一个上出错。**

### [04-共谋盲点与外部检验](04-共谋盲点与外部检验.md)

工程方法论。**同一双手写出的代码与测试，共享同一批盲点。**

核心结论：三种外部检验各自发现自查发现不了的东西——
换考题（域外误执行 92%）、换审查者（8 个数据破坏级缺陷）、换工具（四轮不过变一次全过）。

> 附 29 个变异测试与 136 个缺陷提炼出的 8 条判据。

```powershell
.\论文产生\render.ps1                   # 2. 渲染论文
```

改了代码之后，只需重跑这两条命令，**论文里的数字会自动跟上**。

---

## 为什么这样组织

论文里的每个数字都必须能用一条命令复现。
如果正文直接写字面量，它就成了**需要手工保持同步的第二份事实**——
而本工程已四次因为这种清单分叉而返工。

所以：

- **数字只存在一处**：`measured.json`（脚本产物）
- **论文只引用键**：`{{key}}`，不写字面量
- **渲染器拒绝静默失败**：渲染后若残留 `{{`，直接报错退出

这套做法的代价是论文不能直接手改数字（改了会被下次渲染覆盖）。
这是**故意的**：手改数字正是分叉的起点。
