# 构屎 GOUJI

> **一句话**：用 AI 协作，搓一个**能跑在任何低性能设备上**的微型模型——
> 目标是完成任何任务。

> 目前完成的是**第一块地基**：一个零训练参数的工具路由层，
> 在 8 GB 笔记本 GPU 上跑 0.22 ms/次。距离「任何任务」还很远。
> **这正是邀请你来的原因。**

> ### 本项目的所有文件由 AI 编写
>
> **人类决定做什么、审阅什么、接受或拒绝什么，但不亲手改写文件。**
> 详见 [`AI-ONLY.md`](AI-ONLY.md)。
>
> 这是一条**无法完全验证**的规则——没有任何工具能证明某个字符是生成的还是敲的。
> 所以它被拆成两半：**提交声明由钩子强制检查**（缺了就拒提交），
> **「改动确实由 AI 生成」只能靠声明与审阅**。
> 后者在 `AI-ONLY.md` 第三节里明确标注为**未验证**。

## 这个项目想做什么

今天的能力被硬件绑住了：想让它做点复杂的事，就得租几十 GB 的显卡。
**我们不接受这个前提。**

我们的赌注是：

1. **智能不必须来自大权重**。相当一部分「完成任务」的能力，
   可以由**检索 + 组合 + 少量规则**提供，而不只是前向传播。
2. **权重可以压到 2 bit**。三值 {-1,0,+1} 在带宽受限时比 int4 更快，
   这不是近似，是实测。
3. **写入不该需要训练**。用户教一句就该生效，而不是跑一轮梯度下降。

如果这三条成立，那么「能在任何设备上跑的微型模型」是有路可走的。
**我们不声称已经做到，我们声称这条路值得走，并且已经走通了第一段。**

## 已经做到了什么（全部可复现）

| 能力 | 实测 | 命令 |
|---|---|---|
| 工具路由准确率（留出集，未见句式） | **100%**（1350/1350） | `am-eval --data 6000` |
| 检索延迟 | **0.22 ms**（4400+ 查询/秒） | `am-bench` |
| 写入一条新说法 | **23 µs**，一遍遍历，零梯度 | `am-build` |
| 可训练参数 | **0** | — |
| 三值 vs int4（N=65536，冷 L2） | **1.92x** | `sweep` |
| 三值 vs fp16 | **7.65x** | `sweep` |
| 真实语料域外误执行（英文） | **1.3%** | `am-realclinc --per 50` |
| 真实语料域外误执行（中文） | **0.3%** | `am-realclinc --chinese --per 400` |

**支撑这些的基础设施**（也是给贡献者的）：

- **29 个变异测试**：故意破坏代码，要求对应测试失败。全部被抓住。
- **8 条工程判据**：从 143 个已修缺陷里提炼，见 [`CRITERIA.md`](CRITERIA.md)。
- **指纹**：`canticle fingerprint` → `GOUJI-F7BB-7B3E-DCBB`，
  由模型状态量算出。改了阈值/维度/工具数，指纹就变。
  它不告诉你「能不能跑」，它告诉你**「跑的还是不是同一个模型」**。

## 还没做到什么（诚实清单）

**这是本文件最重要的一节。**

| 目标 | 现状 | 差距 |
|---|---|---|
| 完成**任何**任务 | 只支持 **9 个工具**（读/写/列/执行/算/查/建目录/复制/统计） | **极大** |
| 理解任意自然语言 | 只做**意图分类**，不做对话理解 | 极大 |
| 组合泛化 | **没有**。语料里没有的动词，系统选择拒答 | 结构性缺失 |
| 多步推理 | 支持多轮**上下文继承**，不支持规划 | 大 |
| 在手机/单片机上跑 | 目前需 CUDA。**没有 CPU 后端** | 中等（工作量，非原理） |
| 真正的语言模型 | 有训练代码（`train`/`ftrain`），但规模极小 | 极大 |

**当前的真实定位**：一个**设备端的命令路由层**。
它能把「读一下那个日志」变成 `read_file {"path": "..."}`，
**它不会写代码、不会推理、不会对话**。

如果你要的是「一个能聊天的 GPT」，这不是。
如果你感兴趣的是「**能不能用完全不同的方法做出智能**」，欢迎。

## 为什么值得一起写

**1. 这条路线很少人走，所以每一步都是新的。**

主流是「更大模型 + 更多数据」。我们问的是：
**同样的能力，能不能用小得多的东西换到？** 换到什么程度？
这个问题的答案现在没人知道，包括我们。

**2. 这里的工程标准比多数项目严格。**

变异测试、最小工作量断言、单一真源检查、指纹门禁——
这些不是摆样子，是**每一条都由一个真实事故逼出来的**。
在这里写的代码，会被真的验证。

**3. 失败也是产出。**

`experiments/FINDINGS.md` 记录的不只是成功。
本项目的判据之一是：**负结果和踩坑同样记录，它们是这个项目最贵的资产**。

**4. 门槛低，天花板高。**

低：纯 C++，无第三方库，无 Python。会写 C++ 就能开始。
高：「怎样才算智能」这个问题没有终点。

## 快速开始

```powershell
git clone https://github.com/3145544645/gouji.git
cd gouji
cmd /c build.bat          # 需要 CUDA 13.1 + MSVC 2022 + CMake + Ninja

.\build\canticle.exe fingerprint   # 确认构建完整
.\build\canticle.exe am-test       # 73/73 单元测试
.\build\canticle.exe am-source     # 单一真源检查
```

**依赖**：nvcc 13.1、MSVC 14.44、CMake 3.24+、Ninja。**无第三方 C++ 库。**

**注意**：项目路径**必须是纯 ASCII**。nvcc 在中文路径下会截断路径导致编译失败。

### 克隆后：哪些能立刻跑

| 类别 | 命令 | 可直接跑？ |
|---|---|---|
| 自检 | `fingerprint` `am-test` `am-source` `am-precedence` `am-entries` `criteria` | **是** |
| GPU 基准 | `dev` `bench` `sweep` `ste` | **是**（需 GPU） |
| 纯语法测试 | `am-multi` `am-multi-act` `am-unsupported` | **是**（不读记忆） |
| 自带语料 | `am-eval` | **是** |
| 需要记忆 | `am-para` `am-sem` `am-e2e` `am-turns` `am-bench` | 先 `am-build --data 6000` |
| 需要外部语料 | `am-realclinc` `am-realcase` `am-hunt` | 见 [`corpus/README.md`](corpus/README.md) |

**缺失数据时会明确报错退出**，不会静默用空记忆跑出一堆「拒答」
让你误以为模型坏了——这条规则本身也是被缺陷逼出来的。

## 怎么参与

**任何形式的贡献都欢迎**——代码、实验、反例、文档、提问。

最需要帮助的方向（按优先级）：

1. **CPU 后端**。让它在没有 GPU 的机器上跑。这是「任何低性能设备」的前提。
2. **更多工具**。当前 9 个。加一个工具应该只改一行（`tool_specs()`），
   如果你发现不是，那是缺陷。
3. **组合泛化**。当前最大的能力缺口。任何思路都值得试。
4. **反例**。**如果你能让它出错，那比修一个 bug 更有价值。**

详见 [`CONTRIBUTING.md`](CONTRIBUTING.md) 与 [`ROADMAP.md`](ROADMAP.md)。

## 项目结构

```
src/            核心实现（52 个 .cpp/.cu）
include/        头文件（18 个）
论文产生/        4 篇技术报告，数字由脚本从实测注入
corpus/         语料获取说明（数据不入库）
experiments/    实验记录与负结果
architecture.html  完整架构图（单文件，浏览器打开）
CRITERIA.md     8 条工程判据
mutate.ps1      变异测试驱动
```

**文档**：

- [`architecture.html`](architecture.html) — 完整架构，含 143 个已修缺陷的逐条记录
- [`CRITERIA.md`](CRITERIA.md) — 从缺陷提炼的工程判据，**写代码前读一遍**
- [`论文产生/`](论文产生/) — 4 篇技术报告
- [`STATUS.md`](STATUS.md) — 当前状态快照
- [`USAGE.md`](USAGE.md) — 命令手册

## 明确不做

- **不做通用聊天**。这个项目的目标是「完成任务」，不是「陪聊」。
- **不追求 SOTA 分数**。我们关心的是「用多少资源换到多少能力」。
- **不引入 Python**。这不是洁癖，是约束：依赖越多，能跑的设备越少。
- **不隐藏失败**。所有负结果都在 `experiments/FINDINGS.md` 里。
