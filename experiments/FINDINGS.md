## F-01 三值 vs int4 的性能交叉（实证，2026-10-16）

**现象**：2 bit/权重的位平面格式，是否真比 4 bit 的 int4 快？

**方法**：`canticle sweep`，冷 L2（每轮计时前用 512 MB 缓冲冲刷 L2），
权重规模从 0.5 MB 扫到 268 MB，三种格式同场。

**结果**：

| N | 三值 MB | int4 MB | fp16 MB | 三值 ms | int4 ms | fp16 ms | 胜者 |
|---|---|---|---|---|---|---|---|
| 512 | 0.50 | 1.00 | 4.00 | 0.0186 | 0.0254 | 0.0334 | 三值 |
| 4096 | 4.00 | 8.00 | 32.00 | 0.0356 | 0.0567 | 0.1501 | 三值 |
| 16384 | 16.00 | 32.00 | 128.00 | 0.0895 | 0.1527 | 0.5589 | 三值 |
| 65536 | 64.00 | 128.00 | 512.00 | 0.3000 | 0.5665 | 2.2122 | 三值 |

**结论**：8 个规模**全部胜出**。最大规模下三值比 int4 快 **1.89x**、比 fp16 快 **7.37x**，
有效带宽 223.7 GB/s = 实测拷贝峰值（228.5 GB/s）的 **98%**。
机理：三者都跑满带宽，**三值搬的字节最少**，所以最快。这是「有限配置高速推理」的物理基础。

**复现**：`canticle sweep`

## F-02 三值 STE 训练能泛化（实证，2026-10-16）

**现象**：权重全离散在 {-1,0,+1}，梯度还能不能传下去并真的学到东西？

**方法**：`canticle ste`。任务 = 随机位置标记识别（64 类），前向每次都是三值权重。

**结果**：

| 指标 | 值 |
|---|---|
| 随机基线 | ln(64) = 4.159 |
| 训练 loss | 6.2402 -> **0.0135** |
| **留出测试 loss** | **0.0357 = 0.009 x 基线** |
| **留出测试准确率** | **100.00%**（chance 1.56%） |
| 训练吞吐 | 7299 steps/s |

**结论**：**机制成立**。未见过样本 100% 正确 -> 不是记忆，是真泛化。
三值权重可以在纯 C++/CUDA 下训练，无需任何 Python 框架。

**复现**：`canticle ste --steps 3000 --rq 8`

## F-03 失败的验证任务设计（负结果 x2）

| 尝试 | 训练准确率 | 测试准确率 | 根因 |
|---|---|---|---|
| `(sum ids) mod V` | 81.25% | **0.00%** | 环绕运算是非线性的，**线性头在原理上表达不了** |
| `bucket(sum ids)` | 77.93% | 0.78% | 512 个离散 token 学不出一维数值语义，样本不足 |

**教训**：验证一个训练机制时，**任务必须与模型容量匹配**。
选错任务会让人误判机制失效，浪费一整轮。改为「标记识别」后立即 100% 通过。

## F-04 关键 bug 清单（每条都真实发生过）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| B1 | 全部内核精度 FAIL，误差 9.8e0 | `f16_to_f32(uint16_t)` 收 `__half` 时被隐式转 float 再截断，数据静默损坏 | 加 `__half` 重载防护 |
| B2 | 训练 loss 20 步内变 NaN | Adam 偏置校正 `1-b^0 = 0`，**除零** | 用 `step+1` |
| B3 | loss 从正确起点 6.92 立刻变 NaN | `k_ce_rows` 用 `__shfl_xor_sync` 只做**单 warp** 归约，256 线程下 softmax 只覆盖 1/8 词表 | 改走 shared memory 跨 warp 归约 |
| B4 | 梯度缓冲出现海量非有限值 | `k_attn_fwd` lane 0 写完 `pr[]` 后其他 lane 直接读，**缺 `__syncwarp()`** | 补 barrier |
| B5 | 同上 | `bw_rmsnorm` 用 `+=` 写，却把**激活缓冲**当输出，梯度叠加到激活上 | 独立 `dnorm` 缓冲并清零 |
| B6 | 训练进程静默 exit 1，零输出 | `data.cpp` 里 `pick(0,3)` 索引只有 3 个元素的数组，**越界访问违例** | 每个数组配自己的分布 |
| B7 | 构建脚本谎报 `[OK]` 但 exe 不存在 | `build/` 被清后 `mkdir` 那行也被删，日志重定向失败 | 恢复 `mkdir` 并加 exe 存在性检查 |
| B8 | nvcc 把路径截成三段 | 项目路径含中文，**CUDA 工具链不吃非 ASCII 路径** | 实体目录改 ASCII + junction |
| B9 | `launch_tgemm_dx` 未定义 | 只写了 `__global__` 内核，忘了 host 包装函数 | 补 launcher |

**最重要的一条**：B4/B5 都表现为「权重健康但 loss NaN」。
**看到这个组合，第一反应就该查非赋值写（`+=` / `atomicAdd`）的缓冲与并发内存可见性**，
而不是怀疑学习率或权重爆炸。

## F-05 L2 持久化实验（无效实验，诚实记录）

**假设**：把权重钉死进 32 MiB L2，decode 时 DRAM 流量约等于 0。

**结果**：cold 0.0265 ms -> hot 0.0257 ms，加速 **1.029x**，几乎为零。

**为什么无效**：4 MB 权重**本来就在 L2 里**，pin 与不 pin 无差别。
且实测 **L2 持久化上限 = 22 MiB**（非 32 MiB，以 `cudaDevAttrMaxPersistingL2CacheSize` 为准）。

**教训**：设计 A/B 实验前，先确认**对照组的差异真的存在**。

## F-06 位提取指令开销（负结果）

**假设**：三值 2 bit/权重省带宽，直接替换就能提速。

**结果**：首版每权重约 6 条指令（位提取），比 int4 的约 5 条还多，**慢 12%**。

**修复方向**：必须让访存完全合并 + 减少位运算，而不是单纯减少字节数。
最终通过 warp 分摊字 + `__half2` 向量化才赢回来（见 F-01）。

**教训**：**带宽减半不等于更快**。L2 命中时瓶颈是**指令吞吐**，不是带宽。
这个判据决定了后续所有内核的优化方向。
